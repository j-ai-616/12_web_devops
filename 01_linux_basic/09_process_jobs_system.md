# 09. 프로세스와 작업 관리

## 학습 목표

- 프로세스와 PID의 의미를 이해한다.
- 실행 중인 프로세스를 조회하고 종료한다.
- 포그라운드와 백그라운드 작업을 다룬다.
- 시스템 자원 사용량을 기본 명령어로 확인한다.

## 프로세스란?

프로세스는 실행 중인 프로그램이다. 리눅스는 각 프로세스에 PID라는 고유 번호를 부여한다. 프로세스는 부모 프로세스에서 만들어지며, 셸에서 명령을 실행하면 셸의 자식 프로세스로 실행된다.

## 프로세스 확인

```bash
# 현재 터미널의 프로세스를 출력한다
ps

# 현재 터미널의 프로세스를 자세한 형식으로 출력한다
ps -f

# 시스템 전체 프로세스 중 앞부분만 출력한다
ps aux | head

# 현재 셸의 PID, 부모 PID, 명령 정보를 출력한다
ps -p $$ -o pid,ppid,comm,args
```

| 명령어 | 설명 |
| --- | --- |
| `ps` | 현재 터미널의 프로세스 |
| `ps -f` | 자세한 형식 |
| `ps aux` | 시스템 전체 프로세스 |
| `$$` | 현재 셸의 PID |

프로세스 트리를 보려면 다음을 사용한다.

```bash
# 프로세스 부모-자식 관계를 트리 형태로 출력한다
pstree -p
```

`pstree`가 없으면 설치할 수 있다.

```bash
# pstree가 포함된 psmisc 패키지를 설치한다
sudo apt install psmisc
```

## top으로 실시간 확인

```bash
# 프로세스와 시스템 자원 사용량을 실시간으로 확인한다
top
```

`top` 안에서는 `q`로 종료한다. CPU와 메모리 사용량이 높은 프로세스를 볼 수 있다.

## 백그라운드 작업

오래 실행되는 명령을 백그라운드에서 실행하려면 명령 끝에 `&`를 붙인다.

```bash
# sleep 명령을 300초 동안 백그라운드로 실행한다
sleep 300 &

# 현재 셸의 작업 목록을 확인한다
jobs
```

백그라운드 작업을 포그라운드로 가져온다.

```bash
# 1번 작업을 포그라운드로 가져온다
fg %1
```

포그라운드에서 실행 중인 작업은 `Ctrl + z`로 일시 정지할 수 있다. 정지된 작업을 백그라운드로 계속 실행하려면 다음을 사용한다.

```bash
# 1번 작업을 백그라운드에서 계속 실행한다
bg %1

# 작업 상태를 다시 확인한다
jobs
```

## 프로세스 종료

먼저 실습용 프로세스를 만든다.

```bash
# 종료 실습용 sleep 프로세스를 백그라운드로 실행한다
sleep 600 &

# 현재 작업 목록을 확인한다
jobs

# sleep 프로세스의 PID를 찾는다
pgrep sleep
```

정상 종료 신호를 보낸다.

```bash
# 가장 최근 sleep 프로세스에 정상 종료 신호를 보낸다
kill "$(pgrep -n sleep)"
```

아직 남아 있는지 확인한다.

```bash
# sleep 프로세스가 남아 있는지 확인한다
pgrep sleep
```

강제 종료는 마지막 수단이다.

```bash
# 강제 종료 실습용 sleep 프로세스를 실행한다
sleep 600 &

# 가장 최근 sleep 프로세스에 강제 종료 신호를 보낸다
kill -9 "$(pgrep -n sleep)"
```

`kill -9`는 프로그램이 정리 작업을 할 기회를 주지 않으므로 습관적으로 쓰지 않는다.

## 이름으로 종료

```bash
# sleep 프로세스를 백그라운드로 실행한다
sleep 600 &

# 이름이 sleep인 프로세스를 종료한다
pkill sleep
```

같은 이름의 프로세스가 여러 개 있으면 모두 대상이 될 수 있으니 주의한다.

## 자원 사용량 확인

```bash
# 시스템 실행 시간과 부하 평균을 확인한다
uptime

# 메모리 사용량을 확인한다
free -h

# 파일 시스템별 디스크 사용량을 확인한다
df -h

# linux-class 디렉터리의 전체 용량을 확인한다
du -sh ~/linux-class
```

| 명령어 | 설명 |
| --- | --- |
| `uptime` | 실행 시간과 부하 평균 |
| `free -h` | 메모리 사용량 |
| `df -h` | 파일 시스템 여유 공간 |
| `du -sh` | 특정 디렉터리 사용량 |

## WSL에서의 서비스

WSL은 Windows 안에서 실행되므로 일반 서버의 부팅 과정과 다르다. systemd가 활성화된 WSL에서는 일부 서비스를 `systemctl`로 볼 수 있다.

```bash
# PID 1번 프로세스 이름을 확인한다
ps -p 1 -o comm=

# systemd 상태를 확인한다
systemctl status
```

동작하지 않는다면 해당 WSL 환경에서 systemd가 꺼져 있는 것이다.

4. `top`에서 CPU와 메모리 열을 확인한다.
5. `~/linux-class`의 디스크 사용량을 확인한다.
