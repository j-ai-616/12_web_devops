# 클라우드 개요

## 학습 목표

- 클라우드가 등장한 배경을 설명할 수 있다.
- 온프레미스와 클라우드의 차이를 비용, 속도, 운영 책임 관점에서 비교할 수 있다.
- IaaS, PaaS, SaaS를 구분할 수 있다.
- AWS 서비스를 컴퓨팅, 네트워크, 저장소, 데이터베이스, 보안 영역으로 분류할 수 있다.
- AWS 서비스를 하나의 아키텍처로 연결할 수 있다.

## 1. 클라우드란 무엇인가

클라우드 컴퓨팅은 서버, 저장소, 데이터베이스, 네트워크, 소프트웨어 같은 IT 자원을 인터넷을 통해 필요한 만큼 빌려 사용하는 방식이다. 사용자는 물리 서버를 직접 구매하고 설치하지 않고도 관리 화면이나 API를 통해 몇 분 안에 자원을 만들 수 있다.

클라우드는 단순히 "다른 사람의 컴퓨터"만을 뜻하지 않는다. 자원을 요청하는 방법, 사용량을 측정하는 방식, 자동 확장과 관리형 서비스까지 포함하는 운영 모델이다.

### 온프레미스와 비교

| 관점 | 온프레미스 | 클라우드 |
| --- | --- | --- |
| 자원 준비 | 서버 구매와 설치에 시간이 필요하다. | 콘솔이나 API로 빠르게 생성한다. |
| 비용 | 장비를 먼저 구매하는 자본 비용이 크다. | 사용량에 따라 비용을 지불한다. |
| 확장 | 장비를 추가 구매해야 한다. | 인스턴스 수나 사양을 변경한다. |
| 운영 | 전원, 냉각, 하드웨어까지 관리한다. | 제공자가 물리 인프라를 관리한다. |
| 통제 | 물리 장비까지 직접 통제한다. | 서비스가 허용하는 범위에서 통제한다. |

클라우드가 항상 더 싸거나 더 쉬운 것은 아니다. 사용하지 않는 자원을 방치하면 비용이 계속 발생하고, 권한과 네트워크를 잘못 설정하면 보안 사고로 이어질 수 있다. 빠르게 만들 수 있다는 장점은 빠르게 잘못 만들 수도 있다는 뜻이다.

## 2. 클라우드가 등장한 배경

서비스 사용량은 일정하지 않다. 평소에는 사용자가 적다가 행사나 마케팅 시점에 갑자기 늘 수 있다. 최대 사용량에 맞춰 서버를 구매하면 평소에는 자원이 남고, 평균 사용량에 맞추면 트래픽이 늘 때 장애가 발생한다.

클라우드는 다음 문제를 해결하려고 발전했다.

- 서버 구매와 설치에 걸리는 시간을 줄인다.
- 예상하기 어려운 트래픽 변화에 대응한다.
- 여러 지역에 서비스를 배포하기 쉽게 만든다.
- 반복적인 인프라 작업을 API와 자동화 도구로 처리한다.
- 데이터베이스와 AI처럼 운영이 복잡한 기능을 관리형 서비스로 제공한다.

## 3. 클라우드의 주요 특징

### 주문형 셀프서비스

관리자에게 서버 구매를 요청하지 않고 사용자가 직접 자원을 만든다.

### 네트워크를 통한 접근

인터넷이나 전용 네트워크를 통해 자원에 접근한다.

### 자원 공유

클라우드 제공자는 대규모 물리 자원을 여러 고객에게 논리적으로 분리해 제공한다.

### 빠른 확장과 축소

필요에 따라 자원의 크기나 개수를 조절한다.

### 측정 가능한 사용량

실행 시간, 저장 용량, 요청 수, 전송량 같은 사용량을 측정해 비용을 계산한다.

## 4. IaaS, PaaS, SaaS

| 모델 | 사용자가 주로 관리하는 것 | 대표 예시 |
| --- | --- | --- |
| IaaS | 운영체제, 런타임, 애플리케이션 | Amazon EC2 |
| PaaS | 애플리케이션 코드와 데이터 | 관리형 애플리케이션 플랫폼 |
| SaaS | 서비스 설정과 사용자 데이터 | Gmail, Notion, Slack |

EC2를 사용하면 Ubuntu 패키지, Nginx, Python, Django를 직접 설치한다. 자유도가 높은 대신 운영 책임도 크다. Lambda는 운영체제와 서버 프로세스를 직접 관리하지 않고 함수 코드에 집중한다. 같은 클라우드 안에서도 서비스마다 사용자의 책임 범위가 다르다.

## 5. AWS 서비스의 종류

AWS는 하나의 거대한 프로그램이 아니라 서로 다른 문제를 해결하는 서비스의 모음이다. 웹 서비스를 만들 때 필요한 기능을 조립하듯 선택한다.

| 분류 | 해결하는 문제 | 서비스 |
| --- | --- | --- |
| 컴퓨팅 | 코드를 어디에서 실행할 것인가 | EC2, Lambda |
| 네트워크 | 자원을 어떤 주소와 경로로 연결할 것인가 | VPC, 서브넷, 보안 그룹 |
| 저장소 | 파일과 객체를 어디에 보관할 것인가 | EBS, S3 |
| 데이터베이스 | 구조화된 데이터를 어떻게 저장하고 조회할 것인가 | RDS PostgreSQL |
| 권한 | 누가 어떤 작업을 할 수 있는가 | IAM |
| 컨테이너 | 실행 이미지를 어디에 저장할 것인가 | ECR |
| 운영 | 로그를 보고 원격 명령을 어떻게 실행할 것인가 | CloudWatch, Systems Manager |
| AI·머신러닝 | 학습된 모델을 호출하거나 직접 학습할 것인가 | Bedrock, SageMaker AI |

서비스 이름을 먼저 외우기보다 해결할 문제를 먼저 정하는 것이 중요하다. 예를 들어 파일을 저장해야 한다면 EC2의 디스크에 둘지 S3에 둘지 비교하고, 서버를 계속 실행할 필요가 없다면 EC2 대신 Lambda를 검토한다.

### 관리형 서비스

관리형 서비스는 설치, 패치, 백업, 확장 같은 운영 작업의 일부를 AWS가 대신 수행하는 서비스이다. RDS를 사용하면 PostgreSQL 서버를 직접 설치하지 않아도 되고, Lambda를 사용하면 운영체제를 관리하지 않아도 된다. 다만 데이터 구조, 접근 권한, 애플리케이션 오류까지 AWS가 대신 책임지는 것은 아니다.

## 6. 주요 클라우드 제공자

- AWS는 EC2, S3, RDS, Lambda, Bedrock 등 폭넓은 서비스를 제공한다.
- Microsoft Azure는 Microsoft 제품과 기업 환경의 연동에 강점이 있다.
- Google Cloud는 데이터 분석과 머신러닝 서비스에 강점이 있다.

수업에서는 AWS를 사용하지만 컴퓨팅, 네트워크, 저장소, 데이터베이스, 권한이라는 기본 개념은 다른 클라우드에도 적용된다.

## 7. 리전과 가용 영역

리전은 여러 데이터 센터를 묶은 지리적 영역이다. 서울 리전의 코드는 `ap-northeast-2`이다. 가용 영역은 한 리전 안에서 전원과 네트워크 장애 영역을 분리한 데이터 센터 그룹이다.

사용자는 다음 기준으로 리전을 선택한다.

- 사용자와 가까워 지연 시간이 짧은가
- 필요한 서비스와 모델을 제공하는가
- 데이터 보관 규정에 맞는가
- 예상 비용이 적절한가

이 수업의 모든 자원은 특별한 안내가 없는 한 서울 리전에 생성한다. 리전이 다르면 콘솔에서 자원이 보이지 않는 것처럼 느낄 수 있으므로 실습 시작 때 항상 현재 리전을 확인한다.

## 8. 전체 아키텍처

```text
[학생 PC: WSL]
       |
       | SSH / HTTPS
       v
[AWS VPC]
  [EC2: Nginx -> Django 컨테이너]
       |                  |
       |                  +------> [S3: 객체 저장]
       |
       +-------------------------> [RDS: PostgreSQL]

[git push] -> [GitHub Actions] -> [ECR] -> [SSM] -> [EC2 재배포]
```

이 구조에서 서비스는 다음 질문에 답한다.

| 질문 | 서비스 |
| --- | --- |
| 애플리케이션을 어디에서 실행하는가 | EC2, Lambda |
| 파일을 어디에 저장하는가 | S3 |
| 관계형 데이터를 어디에 저장하는가 | RDS |
| 누가 어떤 자원에 접근할 수 있는가 | IAM |
| 네트워크 접근을 어떻게 제한하는가 | VPC, 보안 그룹 |
| 컨테이너 이미지를 어디에 저장하는가 | ECR |
| 실행 상태와 오류를 어디에서 확인하는가 | CloudWatch |

### 배포가 의미하는 것

배포는 소스 코드를 서버에 복사하는 작업 하나만을 뜻하지 않는다. 애플리케이션이 실제 요청을 받을 수 있도록 다음 요소를 함께 준비하는 과정이다.

1. 소스 코드와 Python 패키지를 준비한다.
2. Django를 실행할 애플리케이션 서버를 구성한다.
3. 외부 요청을 받을 네트워크와 웹 서버를 연결한다.
4. 데이터베이스와 파일 저장소의 접속 정보를 주입한다.
5. 프로세스가 종료되었을 때 다시 시작할 방법을 만든다.
6. 변경된 코드를 검사하고 안전하게 교체한다.

앞부분에서는 이 과정을 EC2에서 수동으로 수행하고, 뒤에서는 Docker와 CI/CD로 반복 작업을 자동화한다.

## 9. 공동 책임 모델

클라우드 제공자는 클라우드 자체의 물리 시설, 하드웨어, 기반 네트워크를 보호한다. 사용자는 계정, 데이터, IAM 권한, 보안 그룹, 운영체제 패치, 애플리케이션 설정을 보호한다.

EC2에서는 운영체제 패치도 사용자의 책임이다. RDS에서는 데이터베이스 서버 운영의 일부를 AWS가 맡지만 데이터베이스 계정과 데이터 접근 정책은 사용자가 관리한다. 관리형 서비스라고 해서 보안 책임이 사라지는 것은 아니다.

## 확인 과제

1. EC2와 Lambda를 IaaS와 서버리스 관점에서 비교한다.
2. 클라우드를 사용해도 사용자가 직접 책임져야 하는 항목을 세 가지 적는다.
3. 수업 전체 아키텍처에서 데이터가 저장되는 서비스를 두 가지 찾는다.
