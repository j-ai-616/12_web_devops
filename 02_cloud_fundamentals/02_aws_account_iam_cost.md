# AWS 계정, IAM, 비용 관리

## 학습 목표

- 루트 사용자와 일반 작업용 사용자를 구분할 수 있다.
- IAM 사용자, 그룹, 역할, 정책의 차이를 설명할 수 있다.
- MFA와 최소 권한이 필요한 이유를 설명할 수 있다.
- Budget과 태그를 사용해 실습 비용을 추적할 수 있다.

## 1. 실습 전 준비

다음 항목을 수업 전에 확인한다.

- AWS 콘솔에 로그인할 수 있다.
- 결제 수단과 연락처가 정상적으로 등록되어 있다.
- 계정 루트 사용자에 MFA가 설정되어 있다.
- 서울 리전 `ap-northeast-2`를 선택할 수 있다.

## 2. 루트 사용자

루트 사용자는 AWS 계정을 만들 때 사용한 이메일 주소로 로그인하는 계정 소유자이다. 모든 자원과 결제 정보에 접근할 수 있으므로 일상적인 실습에 사용하지 않는다.

루트 사용자로 수행할 작업은 다음처럼 제한한다.

- 계정 최초 설정
- 루트 MFA 설정
- 결제 정보 확인
- 일반 관리자 권한으로 처리할 수 없는 계정 작업

루트 사용자의 Access Key는 만들지 않는다.

## 3. IAM 구성 요소

### IAM 사용자

특정 사람이나 오래된 애플리케이션에 연결되는 장기 자격 증명이다. 사람의 콘솔 접근은 가능하면 IAM Identity Center 같은 연동 방식과 임시 자격 증명을 사용한다.

### IAM 그룹

여러 IAM 사용자에게 같은 정책을 적용하기 위한 묶음이다. 그룹 자체로 로그인하지 않는다.

### IAM 역할

사용자나 AWS 서비스가 일정 시간 동안 맡아서 사용하는 권한 묶음이다. 역할은 임시 자격 증명을 발급한다.


### IAM 정책

어떤 작업을 어떤 자원에 허용하거나 거부하는지 JSON으로 정의한다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": ["arn:aws:s3:::예시-버킷/*"]
    }
  ]
}
```

위 정책은 지정한 버킷의 객체를 읽는 작업만 허용한다. `Action`에 `*`, `Resource`에 `*`를 넣으면 편리하지만 권한 범위가 지나치게 넓어진다.

### 인증과 인가

인증은 "누구인가"를 확인하는 과정이고, 인가는 "무엇을 할 수 있는가"를 판단하는 과정이다. 로그인 비밀번호와 MFA는 인증에 가깝고, IAM 정책은 인증된 주체가 수행할 수 있는 작업을 결정한다.

```text
사용자 또는 서비스
  -> 자격 증명으로 인증
  -> IAM 정책으로 권한 평가
  -> 허용된 AWS API 실행
```

로그인에 성공했다고 모든 AWS 작업을 할 수 있는 것은 아니다. 같은 사용자도 연결된 정책에 따라 S3 조회는 가능하지만 EC2 삭제는 거부될 수 있다.

## 4. AWS를 조작하는 세 가지 방법

| 방법 | 특징 | 
| --- | --- | 
| AWS Management Console | 브라우저 화면에서 설정한다. | 
| AWS CLI | 터미널 명령으로 AWS API를 호출한다. | 
| AWS SDK | 애플리케이션 코드에서 AWS API를 호출한다. | 

세 방법은 서로 다른 AWS를 사용하는 것이 아니다. 최종적으로 같은 AWS API에 요청하며, 작업 방식만 다르다. 처음에는 콘솔에서 구조를 확인하고 반복 작업은 CLI나 SDK로 옮긴다.

## 5. 최소 권한과 MFA

최소 권한은 작업에 필요한 권한만 부여하는 원칙이다. 처음에는 관리형 정책으로 실습을 시작할 수 있지만 실제 운영에서는 자원과 작업 범위를 줄인 정책으로 교체한다.

MFA는 비밀번호 외에 인증 앱이나 보안 키를 추가로 요구한다. 비밀번호가 유출되어도 두 번째 인증 요소가 없으면 로그인을 막을 수 있다.

## 6. AWS 콘솔 기본 확인

1. AWS 콘솔에 로그인한다.
2. 화면 상단의 리전 선택 메뉴에서 `서울`을 선택한다.
3. 계정 메뉴에서 현재 로그인 주체가 루트인지 IAM 또는 연동 사용자인지 확인한다.
4. 콘솔 검색창에서 `IAM`을 검색한다.
5. IAM 대시보드에서 보안 권장 사항을 확인한다.

콘솔 화면의 위치는 변경될 수 있지만 서비스 이름과 설정 항목의 의미는 유지된다.

## 7. Budget 만들기

Budget은 예상 비용이나 실제 비용이 기준을 넘을 때 알려 주는 기능이다. Budget을 만들어도 서비스가 자동으로 중지되지는 않는다.

1. 콘솔 검색창에서 `Billing and Cost Management`를 연다.
2. 왼쪽 메뉴에서 `Budgets`를 선택한다.
3. `Create budget`을 선택한다.
4. `Zero spend budget` 또는 월별 비용 예산을 선택한다.
5. 알림을 받을 이메일 주소를 입력한다.
6. 예산과 알림 기준을 확인한 뒤 생성한다.

예산은 실습 범위에 맞게 낮게 잡고 알림 임계값을 여러 단계로 설정한다. 예산 알림 이메일이 스팸함으로 들어가지 않는지도 확인한다.

## 8. 비용을 크게 늘릴 수 있는 선택

다음 자원은 이번 수업에서 만들지 않는다.

- NAT Gateway
- Application Load Balancer
- SageMaker AI 실시간 엔드포인트
- Multi-AZ RDS
- RDS Proxy와 유료 고급 모니터링
- 수업에 필요하지 않은 스냅샷과 Elastic IP

Elastic IP도 퍼블릭 IPv4이므로 무료 고정 주소가 아니다. 현재 AWS는 실행 중인 EC2의 일반 퍼블릭 IPv4와 Elastic IP 모두에 시간당 퍼블릭 IPv4 요금을 부과한다.

## 9. 이름과 태그 규칙

자원 이름을 일정하게 만들면 수업이 끝난 뒤 삭제할 자원을 쉽게 찾을 수 있다.

| 항목 | 수업 값 |
| --- | --- |
| 공통 접두사 | `cloud-class` |
| 리전 | `ap-northeast-2` |
| 태그 키 | `Project` |
| 태그 값 | `cloud-class` |
| 소유자 태그 키 | `Owner` |
| 소유자 태그 값 | 자신의 영문 이름 |

가능한 모든 자원에 다음 태그를 추가한다.

```text
Project = cloud-class
Owner = 자신의 영문 이름
```

## 확인 과제

1. IAM 사용자와 IAM 역할의 가장 중요한 차이를 적는다.
2. Budget을 만들었는데도 비용이 발생할 수 있는 이유를 적는다.
